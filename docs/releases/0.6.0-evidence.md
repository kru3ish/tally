## Defects found during the release audit (all fixed on `main`, none in the tagged build's tests)

1. `tally verify <session>` run from a directory other than the receipt's repository re-judged the session in that directory and overwrote a correct receipt with "tests not run: no consent"; the Evidence Map also scanned that directory's test files for keywords. Found on an evaluation session's receipt ten minutes after its worktree was deleted. Fixed at `7c5f310`: verify follows the repository recorded on the receipt, never re-judges when it is gone, and a tree is scanned only if it contains the receipt's base commit. **Users on 0.6.0 hit this if they run `tally verify <id>` from another project's directory.** The restore path is `judge.prev.json` in the session directory.
2. Generic tokens (JSON, CLI, API, HTTP verbs) counted as keywords a test could "name" a behaviour with. Fixed at `7c5f310`.
3. A touched test file plus a green run anchored any met criterion (the false VERIFIED above). Fixed at `e2888fa`.

## Known limitations carried into the release

- Verdict, quality and ROI are experimental, labelled so, and rest on a model score and an estimated human value.
- A test that names a behaviour but does not exercise it still anchors VERIFIED (mutation verification is roadmap v1.0).
- "Existing behaviour unchanged" criteria are judged, not verified; SUPPORTED is their ceiling and the model's reading can still be generous (logger-vague rerun c4).
- The blind grader is the same model family as the builder; correlated blind spots are reduced by process isolation, not removed. The human-graded set (11 sessions, 51% exact) remains the reference.
- Trusted publishing to npm is not configured; releases are published manually.
